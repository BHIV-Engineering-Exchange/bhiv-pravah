## 1. Entry Point

**File:** `backend/routes/coreExecution.js`
**Route:** `POST /core/execute-from-text`

Accepts a natural language prompt from the frontend Intent Compiler panel, calls the Prompt Runner (Groq AI), converts the response to an execution schema, stores it in the registry, and triggers `dispatchExecution()` — which initializes the Game State Engine session before dispatching engine jobs.

**Flow:**
```
Prompt
  → Prompt Runner (Groq AI)
  → convertToExecutionSchema()
  → storeExecution()
  → dispatchExecution()
  → stateInitializer
  → GSM Session Created
  → Job Dispatch
  → Engine Runtime
```

---

## 2. Core Execution Flow

### File 1 — `backend/executionDispatcher.js`

Converts an execution schema into engine jobs using template selection and parameter injection.

- Calls `stateInitializer.initializeFromExecutionSchema()` to create a GSM session before any jobs are dispatched.
- On dispatch failure, destroys the orphaned GSM session via `gsm.destroySession()`.

---

### File 2 — `backend/state/stateEventProcessor.js`

Sits between the engine socket and the Game State Manager.

- Normalises raw engine events into a standard format.
- Enriches events with derived deltas (`score_delta`, `health_delta`, `entity_type`).
- Calls `gsm.applyEventToState()`.
- Returns `{ success, state, changes }` so the consequence compiler can act on the updated state immediately.

---

### File 3 — `backend/state/gameStateManager.js`

Single source of truth for all active gameplay sessions.

- Holds an in-memory `Map` keyed by `sessionId`.
- State is only mutated via `applyEventToState()`.
- `getCurrentState()` always returns a deep-frozen snapshot.
- Supports all 12 event types defined in `runtimeEvents.js`.

## 6. Failure Cases

### Invalid Runtime Event
`stateEventProcessor.processEvent()` calls `validateRuntimeEvent()` from `runtimeEvents.js`.
If `event_type` is missing, unknown, or `timestamp` is not a number — validation fails.
Returns `{ success: false, error: "Invalid event: ..." }`. State is not mutated. No jobs are dispatched.

### State Corruption Attempt
`stateIntegrityGuard.validateState()` checks all fields on every state object.

Violations caught:
- `player.health > player.max_health`
- `player.health === 0` but `is_alive === true`
- `meta.last_updated_at < meta.created_at`

`guardedApply()` blocks the mutation before it reaches GSM. `validateTransition()` also runs post-mutation as a second layer.

### Invalid Consequence Rule
`consequenceCompiler.initialize()` loads and validates `consequenceRules.json` at startup.
Rules missing `on`, `if`, or `then` are rejected at load time.
At runtime, `matchRules()` only returns rules whose conditions fully match — unmatched rules produce zero jobs silently.

### Event Flood
Each event is processed synchronously through `stateEventProcessor.processEvent()`.
Terminal sessions (`game_over`, `completed`) reject all further events immediately — `applyEventToState()` returns `{ success: false, error: "Session is game_over" }` without touching state.
No queue overflow risk — the GSM Map is bounded by active sessions only.

### Replay Mismatch
`replayReconstructor.reconstruct()` sorts the event trace by `timestamp` before replaying.
Events are applied to an isolated `replay_<sid>_<ts>` session that is destroyed after reconstruction.
If the snapshot file is missing, `_loadInitialSnapshot()` returns `{ success: false }` and reconstruction aborts cleanly without touching any live session.

## 7. Determinism Proof

### Same Prompt → Same Execution Schema
The Prompt Runner (Groq AI) returns the same `game_mode`, `player_params`, `spawn_rules`, and `physics` fields for the same prompt text.
`convertToExecutionSchema()` applies deterministic keyword matching (`topicLower.includes('arena')` → `open_scene`) with no randomness.
The only non-deterministic fields are `execution_id` and `trace_id` (timestamps) — they do not affect state shape.

### Same Events → Same State Transitions
`gameStateManager._applyMutation()` is a pure switch statement.
Given the same `event_type` and `context`, it always produces the same state delta.
`Math.max` and `Math.min` clamps are deterministic. No random values are introduced during mutation.

### Replay Consistency
`replayReconstructor.reconstruct()` loads the initial snapshot (v0), sorts events by timestamp, and replays them in an isolated session.
The final state of the replay session matches the final state of the original session because the same mutation functions are called in the same order with the same inputs.

|---|---|---|

| `player.score` | `gameStateManager.js` → `SCORE_UPDATE` | `validateTransition()` (score never decreases) |

| `player.is_alive` | `gameStateManager.js` → `HEALTH_CHANGED` (health=0) + `PLAYER_DEATH` | `validateState()` (health=0 → is_alive=false) |
| `player.active_powerups` | `gameStateManager.js` → set at creation | `validateState()` |
| `entities.enemy_count` | `gameStateManager.js` → `ENTITY_SPAWNED` / `ENTITY_DESTROYED` | `validateState()` (≥ 0) |
| `entities.obstacle_count` | `gameStateManager.js` → `ENTITY_SPAWNED` / `ENTITY_DESTROYED` | `validateState()` (≥ 0) |
| `entities.collectible_count` | `gameStateManager.js` → `PICKUP_COLLECTED` / `ENTITY_DESTROYED` | `validateState()` (≥ 0) |

| `world.level` | `gameStateManager.js` → `LEVEL_COMPLETE` | `validateTransition()` (level never decreases) |
| `world.difficulty` | `gameStateManager.js` → `LEVEL_COMPLETE` | `validateState()` (≥ 1) |
| `world.time_elapsed` | `gameStateManager.js` → `TIMER_EXPIRED` | `validateState()` (≥ 0) |
| `world.theme` | `gameStateManager.js` → set at creation | — |
| `world.physics` | `gameStateManager.js` → set at creation | — |
| `status` | `gameStateManager.js` → `GAME_START`, `GAME_END`, `PLAYER_DEATH` | `validateTransition()` (ALLOWED_TRANSITIONS map) |
| `meta.event_count` | `gameStateManager.js` → every `applyEventToState()` | `validateTransition()` (must increment by exactly 1) |
| `meta.snapshot_version` | `stateSnapshot.js` → `_bumpSnapshotVersion()` | `validateState()` (≥ 0) |

3. VERIFY authorize_execution() CONTRACT
----------------------------------------
The contract requires `capability_id` and `action`. Inside `ExecutionRightsAdapter.resolve_mapping()` it:
- Discovers capability via `discovery.discover_by_id()`
- Looks up the `VERIFIED_CAPABILITY_MAPPINGS`
- Validates that `status == "VERIFIED"` and the required `evidence` file exists and has the required lines.
- Builds a signed `Execution Rights Authorization` via `generate_execution_payload()`. 
`main.py` is now properly invoking this and handling the returned payload.

4. VERIFY build_execution_contract()
------------------------------------
- `build_execution_contract()` takes a `DecisionContract`, `execution_payload`, and `approved_by`. It normalizes the payload, calculates an `execution_hash`, and produces an `ExecutionContract` object.
- **Why `approved_by="sarathi"`?** `sarathi` refers to the Golang executor module (`bhiv-sarathi`). Repository evidence (`backend/executer/guard.py` showing `SERVICE_ID = "sarathi"`, `executer/app.py` line 149 strictly validating `X-CALLER == "sarathi"`, and `ENGINEERING_AUDIT.md`) confirms that the Golang gateway cryptographically restricts executions to the `sarathi` public key. By assigning `approved_by="sarathi"`, we mathematically bind the execution approval identity to the gateway's expected signature validator.

5. VERIFY THE EVIDENCE PATH FIX
-------------------------------
The `ExecutionRightsAdapter` evaluates evidence paths relative to `PROJECT_ROOT`, which is statically computed via `Path(__file__).resolve().parents[3]` (evaluating to `pravah-bhiv`). 
- **The old path**: `contracts/execution_contract.py` evaluated to `pravah-bhiv/contracts/execution_contract.py`. This file does not exist (it resides in `backend/contracts/...`), meaning the old production code actually crashed (`MappingNotFound` raised by `is_file() == False`).
- **The new path**: `backend/contracts/execution_contract.py` correctly resolves to `pravah-bhiv/backend/contracts/execution_contract.py`. The unit tests historically passed because they mocked the dictionary directly.
- The path correction was independently proven by running E2E tests utilizing native mapping evaluation, which pass with the new path but fail with the old path.

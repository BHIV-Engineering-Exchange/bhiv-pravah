# Frontend API Contracts — React / TypeScript

**Updated:** 2026-07-09  
**Sprint:** SHAKTI Production Convergence Sprint — Energy Intelligence Platform Production Transition  
**Validated by:** 8 integration tests in `tests/test_control_plane_sprint.py` (all PASS)

This document describes the **live KPI**, **system health**, and **alerts** APIs exposed by `control_plane_service.py` (port **8009**). All sample JSON below is taken from real sprint evidence captures under `evidence/api_evidence/`.

---

## 1. Live update model

| Mechanism | Supported? | Notes |
|---|---|---|
| **HTTP polling (REST)** | **Yes — use this** | All dashboard data is served via `GET` JSON endpoints |
| **WebSockets** | **No** | Not implemented anywhere in the codebase |
| **Server-Sent Events (SSE)** | **No** | Not implemented |

The runtime manager refreshes service health every **5 seconds** (`runtime_manager/state/runtime_status.json`). The telemetry service autonomous loop defaults to **30 seconds** (`TELEMETRY_AUTO_INTERVAL_SECONDS`).

### Recommended frontend polling intervals

| UI section | Endpoint(s) | Suggested interval |
|---|---|---|
| Executive KPI strip | `GET /dashboard/executive` | 15–30s |
| System health banner | `GET /system/status` | 5–10s |
| Operations / service grid | `GET /dashboard/operations` | 5–10s |
| Live metrics (throughput, latency) | `GET /metrics` | 10–15s |
| Alerts panel | `GET /dashboard/alerts` | 5–10s |
| Telemetry feed | `GET /dashboard/telemetry` | 10–15s |
| Runtime detail (restarts, PIDs) | `GET /dashboard/runtime` | 5–10s |

Use `setInterval` + `fetch` / `axios`, or React Query / SWR with `refetchInterval`.

## 2. Base URL and headers

| Environment | Base URL |
|---|---|
| Local | `http://127.0.0.1:8009` |
| Docker Compose | `http://127.0.0.1:8009` |
| Render (example) | `https://<control-plane-service>.onrender.com` |

### Authentication

`control_plane_service.py` **does not** enforce auth middleware on its public dashboard routes today. No `X-API-Key` header is required for the endpoints in this document.

Other services (e.g. `POST /pipeline/execute`, `POST /telemetry/ingest`) **do** require `X-API-Key` when `AUTH_ENABLED=true`.

### CORS

CORS is **not** configured on the control plane service. For local React dev (`localhost:5173`), use one of:

- Vite/webpack **dev proxy** to `http://127.0.0.1:8009`
- A backend gateway that adds CORS headers
- Same-origin deployment (frontend served behind the same host)

## 4. TypeScript contracts

```typescript
// --- Shared primitives ---

type ServiceStatus = "healthy" | "unhealthy" | "CRASH_LOOPING" | string;
type OverallStatus = "ok" | "degraded";
type AlertSeverity = "critical" | "high" | "unknown";
type SignalClassification = "nominal" | "warning" | "critical";

export interface RuntimeServiceState {
  status: ServiceStatus;
  pid: number | null;
  port: number;
  restarts: number;
  last_restart_at: string | null; // ISO 8601 UTC
}

export interface Signal {
  signal_id: string;
  trace_id: string;
  metric: string;
  value: number;
  unit: string;
  classification: SignalClassification;
  threshold_breached: boolean;
  derived_at: string;
  source_module_id: string;
  status: string;
  prompt: string;
}

export interface Alert {
  alert_id: string;
  trace_id: string;
  severity: AlertSeverity;
  reason: string;
  signal: Signal;
  decision_summary: {
    gate_status: string;        // e.g. "ALLOWED" | "REJECTED"
    execution_status: string;   // e.g. "success" | "error"
    pipeline_status: string;    // e.g. "success" | "rejected" | "error"
  };
  source_module_id: string;
  status: string;
  raised_at: string;            // ISO 8601 UTC
}

export interface TelemetryRecord {
  source_id: string;
  metric: string;
  value: number;
  unit: string;
  timestamp: string;
  site?: string;
  trace_id: string;
  source_module_id: string;
  status: string;
}

// --- Endpoint responses ---

export interface HealthResponse {
  status: "ok";
  service: "control_plane";
}

export interface MetricsResponse {
  active_services: number;
  services: Record<string, RuntimeServiceState>;
  request_throughput_req_min: number;
  error_rate_pct: number;
  latency_ms: { p50: number; p95: number };
  active_alert_count: number;
  replay_queue_depth: number;
  system_uptime_seconds: number;
}

export interface SystemStatusResponse {
  overall_status: OverallStatus;
  services: Record<string, RuntimeServiceState>;
  uptime_seconds: number;
  active_alerts: number;
  last_replay_check: string;
}

export interface DashboardExecutiveResponse {
  total_pipeline_executions_today: number;
  success_rate: number | null;   // currently null — not computed server-side yet
  active_alerts_by_severity: Record<string, number>;
  overall_system_status: OverallStatus;
}

export interface ServiceMeshEntry {
  health: {
    status: string;
    last_check: string | null;
    response_time_ms: number | null;
  };
  circuit_breaker: {
    state: string;           // e.g. "closed" | "open"
    failure_count: number;
  };
}

export interface DashboardOperationsResponse {
  runtime_services: Record<string, RuntimeServiceState>;
  service_mesh: Record<string, ServiceMeshEntry>;
}

export interface DashboardAlertsResponse {
  alerts: Alert[];
}

export interface DashboardRuntimeResponse {
  generated_at: string;
  services: Record<string, RuntimeServiceState>;
  uptime_seconds: number;
  shutting_down: boolean;
}

export interface DashboardTelemetryItem {
  trace_id: string;
  telemetry: TelemetryRecord | null;
  signal: Signal | null;
}

export interface DashboardTelemetryResponse {
  recent_telemetry: DashboardTelemetryItem[];
  classification_breakdown: Record<SignalClassification, number>;
}
```

## 7. React / TypeScript fetch example (polling)

```typescript
const CONTROL_PLANE_BASE = import.meta.env.VITE_CONTROL_PLANE_URL ?? "http://127.0.0.1:8009";

async function fetchJson<T>(path: string): Promise<T> {
  const res = await fetch(`${CONTROL_PLANE_BASE}${path}`);
  if (!res.ok) throw new Error(`${path} failed: ${res.status}`);
  return res.json() as Promise<T>;
}

// Example: poll system health every 10s
export function useSystemStatus(refetchMs = 10_000) {
  const [data, setData] = React.useState<SystemStatusResponse | null>(null);
  const [error, setError] = React.useState<string | null>(null);

  React.useEffect(() => {
    let cancelled = false;

    const load = async () => {
      try {
        const json = await fetchJson<SystemStatusResponse>("/system/status");
        if (!cancelled) {
          setData(json);
          setError(null);
        }
      } catch (e) {
        if (!cancelled) setError(e instanceof Error ? e.message : "fetch failed");
      }
    };

    load();
    const id = setInterval(load, refetchMs);
    return () => {
      cancelled = true;
      clearInterval(id);
    };
  }, [refetchMs]);

  return { data, error };
}
```

## 8. Error handling

| HTTP status | Meaning | Frontend action |
|---|---|---|
| `200` | Success | Render data |
| `404` | Endpoint or upstream resource missing | Show empty state |
| `500` | Server error | Retry with backoff; show degraded banner |
| Network error | Control plane unreachable | Show offline state; use `overall_status: "degraded"` styling |

There is no pagination on alerts or telemetry endpoints today — lists are capped server-side (alerts ~100, telemetry ~50).

## 10. Summary for frontend team

1. **Use HTTP polling** — no WebSockets or SSE exist today.
2. **Primary service:** `control_plane_service` on port **8009**.
3. **Key endpoints:** `/system/status`, `/metrics`, `/dashboard/executive`, `/dashboard/alerts`.
4. **Auth:** not required on control-plane dashboard routes currently.
5. **CORS:** configure a dev proxy or deploy same-origin.
6. **`success_rate`** on executive dashboard is `null` until backend implements it — handle gracefully in UI.
